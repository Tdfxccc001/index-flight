# v0.7.4 过排停顿修复

## 原因与修复

补排安全规划超过 0.4 秒提交期限时，游戏会保留当前逻辑时刻等待结果。此前等待期间仍持续渲染相同的场景，在 CPU/GPU 争抢资源时进一步延长等待。生产包的软件渲染压力课程中复现了秒级等待；这不等于已经对用户的在线浏览器进行了性能采样，也不能据此认定 GitHub Pages 网络导致卡顿。

- 规划中多个目标通道会被限幅到相同转向。每个父节点只计算一次相同输入的飞行和碰撞结果，保留原选择顺序、排序、裁剪和逻辑访问数。
- 飞行搜索交替复用两个临时状态，仅为保留的分支终态分配对象。实际游戏和搜索仍使用同一套物理计算。
- 等待安全规划时仅渲染一次静止场景；输入、暂停和动画帧调度继续工作。结果到达即恢复绘制。重开、窗口尺寸和设置变化会使等待画面缓存失效。

物理步长、排距、提交期限、搜索宽度、反应时间、安全余量、随机序列、难度、分数、材质和画质均未调整。不跳过安全检查，也不在计算超时时直接接受候选。

## 验证

Windows Chrome 默认 GPU 路径、正式压缩发布包、完整效果开启，测试专用低柱课程运行到至少 20 秒逻辑时间。它覆盖补排和过排渲染；真实难度另由轨迹回放测试覆盖。

| 指标 | 1280×800 | 390×800 |
| --- | ---: | ---: |
| 已通过横排 | 16 | 16 |
| 累计规划等待 | 0 ms | 0 ms |
| 规划往返最大耗时 | 356.9 ms | 308.2 ms |
| 超过 50 ms 的帧 | 1 | 1 |

两种尺寸最终分数相同。强制慢规划检查中，350 ms 内只绘制一次，逻辑时间保持 0，Escape 可暂停，提交结果后恢复前进。默认 GPU 路径指没有强制 SwiftShader，不等于真实手机测量或所有设备的性能保证。

37 项逻辑测试全部通过，含 12,000 组飞行状态与冻结旧实现逐字段对比，以及 20 个历史场景的完整规划证书、访问数和终态精确对比。48 组行情绘制缓冲、HUD、Worker 取消、5 种生成及降级场景、计分轨迹浏览器回归通过。生产子路径及离线测试分别覆盖桌面和手机尺寸。

`node scripts/pages-performance.mjs --hardware` 检查默认 GPU 路径；去掉 `--hardware` 可运行 SwiftShader 压力场景，`--worker-only` 可隔离渲染连续检查 Worker。脚本仅在本地 HTTP 响应副本中注入测试入口，不修改 dist 文件、不向生产页面暴露调试入口。原始性能记录写入被忽略的 test-results；不同渲染路径和并行系统负载下的耗时不能直接用于计算提速百分比。

旧开发性能脚本已补上桌面待起飞状态的启动操作，防止测试等待一个实际上尚未开始的课程。
